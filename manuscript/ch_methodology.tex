\chapter{Systematic Literature Review}
\label{ch:slr}

Kitchenham's guidelines were originally developed for evidence-based
software engineering and have become one of the most widely adopted 
standards for conducting systematic literature reviews in computer 
science \cite{kitchenhamProceduresPerformingSystematic2004a}. The methodology provides 
domain-specific procedures for planning, searching, selecting, and 
synthesizing studies in areas where research outputs are heterogeneous, 
such as machine learning architectures or engineering pipelines. 
Unlike biomedical-focused protocols such as 
PRISMA \cite{moherPreferredReportingItems2009a}, which were designed for clinical 
trials with standardized quantitative outcomes, Kitchenham addresses 
challenges specific to computational research: diversity of study 
designs, inconsistent terminology, non-uniform evaluation metrics, 
and code-based artifacts instead of comparable statistical datasets. 
Frameworks like SALSA \cite{boothSystematicApproachesSuccessful2012} emphasize 
high-level structuring but do not prescribe step-by-step operational 
procedures for reproducibility.

For this thesis, a Kitchenham-style SLR is needed because the SVG 
generation literature consists of diverse model architectures, 
varied input modalities, and different evaluation criteria. 
Kitchenham's protocol provides structured phases 
(planning, conducting, and reporting) that guide the reviewer through 
research question formulation, search strategy definition, 
study selection, quality assessment, data extraction, and 
narrative synthesis. This structure minimizes bias and ensures that 
the review captures the full range of relevant approaches.

\paragraph{Study Selection Criteria}

\subparagraph{Inclusion Criteria:}
\begin{itemize}
    \item \textbf{Language and Publication:} Written in English and published in a peer-reviewed journal, conference, or workshop.
    \item \textbf{Time Range:} Published between 2020--2025 (post-emergence of modern SVG generative models such as DeepSVG).
    \item \textbf{Domain Relevance:} Falls within computer vision, computer graphics, AI, machine learning, or deep learning.
    \item \textbf{Reproducibility:} Provides an open-source implementation or references a publicly available repository. Source code alone is sufficient if the method is reproducible.
    \item \textbf{SVG Output Requirement:} Describes a model or architecture that directly generates SVG or structured vector outputs, including B\'{e}zier curves, SVG \texttt{<path>} commands, layered or hierarchical SVG structure, vector strokes, or structured outputs suitable for editability analysis.
    \item \textbf{Input Modalities:} Supports at least one of: image-to-SVG vectorization, text-to-SVG generation, or multimodal SVG generation.
    \item \textbf{Architectural Transparency:} Provides sufficient technical detail to extract the model architecture and internal SVG representation.
    \item \textbf{Evaluation:} Provides quantitative metrics and qualitative SVG examples that allow analysis of structural quality and editability.
\end{itemize}

\subparagraph{Exclusion Criteria:}
\begin{itemize}
    \item \textbf{No Vector Output:} The method does not generate vector or SVG outputs (pixel-only image generation).
    \item \textbf{Non-ML Methods:} Purely rule-based or classical algorithmic vectorization methods without machine learning or deep learning.
    \item \textbf{Closed-Source Systems:} No publicly available code, weights, or sufficient technical detail for reproduction.
    \item \textbf{Insufficient Evaluation:} Papers lacking SVG evaluation, qualitative vector examples, or structural analysis of outputs.
    \item \textbf{Out-of-Scope Vector Work:} Studies focused on vector editing, rendering, compression, markup optimization, or stylistic modification without SVG generation.
    \item \textbf{Domain Mismatch:} Handwriting synthesis, font generation, datasets, or sketch generation not intended for SVG graphics.
    \item \textbf{Temporal Exclusion:} Studies published before 2020, except when cited for background context only.
    \item \textbf{LLM Restriction:} Exclude proprietary LLMs that generate SVG text but do not provide architecture, training details, or reproducibility.
\end{itemize}

\paragraph{Study Selection Procedure}

\begin{itemize}
    \item Initial records
    \item Duplicate removal
    \item Title/abstract screening
    \item Full-text assessment
    \item Final model selection for analysis
\end{itemize}

\subsection{Duplicate Removal}

After merging all search results, duplicate records (including repeated titles and preprint-conference duplicates) were removed, resulting in 72 unique studies.

\subsection{Study Selection}

\paragraph{Stage 1: Title and Abstract Screening.}
A title and abstract screening excluded works clearly unrelated to SVG generation (e.g., sketch-only models, raster methods, classical vectorization, or closed-source LLMs), reducing the set from 72 to 37 papers.

\paragraph{Stage 2: Full-Text Screening.}
Each of the 37 papers was examined for reproducibility, architectural transparency, and whether it produced SVG or structured vector outputs as defined by the inclusion criteria. In total, 23 studies were excluded at this stage for the reasons listed in Table~\ref{tab:exclusion-reasons}. Following this screening, 14 studies remained as the primary models for the comparative analysis in Chapters~4 through~8.
