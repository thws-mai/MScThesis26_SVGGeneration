\chapter{Vector Representation in SVG Generation}
\label{ch:representation}

SVG generation models differ not only in their architectures and 
training objectives but also in how they represent vector graphics 
internally during the generation process. While all approaches 
ultimately produce SVG files as output, the internal representation 
used during learning or optimization varies considerably across 
methods. This variation has direct consequences for how geometry is 
parameterized, how supervision signals are applied, and what 
structural properties the resulting graphics have.

In the context of this thesis, representation refers to the 
intermediate form in which a model encodes vector geometry, not 
the final output file but the internal structure through which 
shapes are created, manipulated, and decoded. The four 
representation types introduced in 
Chapter~\ref{ch:Background} each encode the same underlying 
geometry differently, and this difference shapes how the model 
learns, how gradients propagate, and what the generated SVG 
looks like structurally.

The chapter works through four representation families 
(parametric, sequential, implicit neural, and latent) as 
they appear across the selected models, then examines what 
each one does to the structure and editability of the output. 
Figure~\ref{fig:representation_outputs} gives an immediate 
sense of the differences: four models, four representations, 
the same subject.


\section{Parametric Representations}

Parametric representations are the closest to how SVG already 
works. Every path is stored as B\'{e}zier control points, stroke 
attributes, and fill colors, exactly the parameters that appear 
in the file itself 
(Section~\ref{sec:vector_fundamentals}). Once DiffVG made 
rasterization 
differentiable~\cite{liDifferentiableVectorGraphics2020a} 
(Section~\ref{sec:diffvg}), these parameters became directly 
optimizable against image-based or semantic objectives. LIVE, 
SAMVG, VectorFusion, and SVGDreamer are all built on this 
foundation~\cite{maLayerwiseImageVectorization2022, 
zhuSAMVGMultistageImage2023, 
jainVectorFusionTexttoSVGAbstracting2022, 
xingSVGDreamerTextGuided2024}.

In theory, this should make parametric outputs the most editable 
of any representation, since every shape is an explicit geometric 
object a designer can select. In practice, that breaks down at 
scale. LIVE uses 160 paths across five layers to represent a 
single image~\cite{maLayerwiseImageVectorization2022}. Open 
that output in Illustrator and the problem is immediate: the 
image looks fine, but selecting a single object means clicking 
through dozens of overlapping fragments that do not correspond 
to any recognizable component. The underlying issue is that 
when optimization needs to capture fine visual detail, it adds 
more paths rather than making existing ones more expressive. 
SVGDreamer++ identifies this path 
entanglement explicitly as a failure mode of optimization-based 
parametric 
methods~\cite{xingSVGDreamerAdvancingEditability2025}.

\section{Sequential Representations}

Sequential models produce the most compact and organized outputs in 
the entire analyzed set, at least within their training domain. 
Paths are few, shapes are distinct, and the resulting SVG files 
are small enough to read by hand. The reason is that sequential 
representations treat vector graphics as ordered sequences of 
drawing commands, mirroring the actual structure of SVG path data.

The sequential formulation traces back to SketchRNN 
(Section~\ref{sec:sequential_repr}), and DeepSVG extended 
it to structured SVG icons using a hierarchical VAE with a 
transformer 
decoder~\cite{carlierDeepSVGHierarchicalGenerative2020}.
DeepIcon~\cite{bingDeepIconHierarchicalNetwork2024} follows the 
same sequential formulation for icon generation. Rather than 
storing shapes as independent geometric objects, these models 
generate a series of commands that describe how the graphic is 
constructed step by step.

The catch is that the representation puts a practical ceiling on 
complexity. Every additional command in the sequence increases the 
chance that prediction errors accumulate and break what comes after. 
This is why sequential models work well for icons (short sequences, 
simple structure) but struggle with complex scenes. DeepSVG trains 
on SVG-Icons8~\cite{carlierDeepSVGHierarchicalGenerative2020}, 
which consists of simple icons with small path counts, and the 
outputs reflect that constraint. There is also a more fundamental 
limitation: a procedural command sequence does not encode explicit 
spatial hierarchy. The model generates commands in order but nothing 
in the representation directly encodes which commands belong to 
which semantic region. Editability is therefore limited even when 
visual reconstruction quality is high.



\section{Implicit Neural Representations}

NeuralSVG represents each SVG as a set of shape indices, where 
each index corresponds to a single shape, and a small MLP learns 
to map these indices to B\'{e}zier control points and fill 
colors~\cite{polaczekNeuralSVGImplicitRepresentation2025}. The 
network weights are the representation, not the shapes themselves. 
This is a fundamentally different approach from storing control 
points or commands explicitly: the geometry only exists when you 
query the network for it. The model maintains stable shape 
correspondence during training, meaning each index always maps to 
the same visual region, which prevents the network from producing 
inconsistent outputs across iterations. NiVeL follows a related 
approach, encoding the entire layered structure implicitly where 
each layer is defined by a continuous neural function over the 
image 
domain~\cite{thamizharasanNIVeLNeuralImplicit2024}, enabling 
clean layered decompositions without explicit path initialization.

The outputs from both models tend to look globally coherent. 
Layers are clean, shapes do not bleed into each other, and the 
overall composition holds together in a way that purely parametric 
outputs often do not. The cost is that individual shapes are not 
directly accessible until the network output is converted into 
discrete primitives, and how clean that conversion is determines 
whether the final SVG supports practical editing.

\section{Latent Representations}

As established in Section~\ref{sec:latent_repr}, a latent space 
is not a geometric representation but an organizational layer 
that sits on top of one. The actual geometry is always produced 
by a decoder that translates latent vectors back into parametric 
paths or sequential commands. What the latent space contributes 
is compression: many graphics mapped into a shared numerical 
embedding learned during training.

DeepSVG applies this by encoding path command sequences into latent 
vectors and training a transformer decoder to reconstruct 
them~\cite{carlierDeepSVGHierarchicalGenerative2020}, building on 
the VAE framework~\ref{sec:latent_repr}. The latent space captures 
structural regularities across the training dataset, enabling 
sampling of new SVGs by decoding from this space.

SVGFusion~\cite{xingSVGFusionScalableTexttoSVG2025} extends this 
further by running a diffusion process entirely within the learned 
latent space of a pretrained vector encoder, rather than in pixel 
space. T2V-NPR takes a different approach, arguing that global 
SVG-level latent spaces are too constrained to capture diverse 
path combinations, and instead learns a neural path representation 
at the individual path 
level~\cite{zhangTexttoVectorGenerationNeural2024}. Generation is 
fast and the outputs feel stylistically consistent, but adjusting 
one specific shape requires navigating latent space rather than 
clicking a path, which is not how designers work.


\section{Representation Boundaries in Practice}
\label{sec:hybrid}

The four families described above are useful for analysis, but 
most models do not stay cleanly inside one. VectorFusion and 
SVGDreamer optimize parametric primitives directly while using 
a latent diffusion model as the semantic prior. The parametric 
layer provides geometric interpretability (every path is a 
readable object), while the latent model provides the semantic 
coherence that pure geometric optimization cannot achieve on 
its own. Without the diffusion prior, optimization would 
match pixels but not meaning. SVGFusion takes a similar 
combined approach, encoding path-level structure into latent 
embeddings before applying diffusion, which allows it to 
generate SVGs that reflect dataset-level structural patterns 
rather than converging from random initialization.

NeuralSVG's core representation is implicit (an MLP mapping 
shape indices to geometry), but it borrows an ordered 
assignment mechanism from 
DeepSVG~\cite{polaczekNeuralSVGImplicitRepresentation2025} 
that imposes explicit hierarchy on what would otherwise be a 
purely neural representation. The result is that each shape 
index consistently maps to the same visual region across 
iterations, which stabilizes training and produces 
outputs where individual shapes can be identified and 
separated. LayerTracer crosses a different boundary: its 
training data is sequential (step-by-step construction 
sequences from the Serpentine 
dataset~\cite{songLayerTracerCognitiveAlignedLayered2025}), 
but the output is a layered parametric SVG where each layer 
corresponds to a meaningful visual component. Because the 
model learns from how designers actually build graphics, it 
absorbs layer separation and construction order as structural 
conventions rather than discovering them through optimization.

These combinations exist because no single representation 
handles visual realism, structural clarity, and editability 
at the same time. Each combination trades something for 
something else, and those trade-offs become visible in the 
structural analysis of Chapter~\ref{ch:synthesis}.

\section{Representation, Editability, and Structural Outcomes}
\label{sec:repr_editability}

Open any SVG in Illustrator or Figma and you expect to click on a 
shape and move it. SVGs are built from individually selectable 
elements, that is the whole point. Whether an AI-generated SVG 
actually supports that depends more on how the model represents 
geometry internally than on how the rendered output looks.

The four rockets in Figure~\ref{fig:representation_outputs} show 
what this means in practice. DeepSVG produces the rocket as a 
monochrome icon with around 15 to 30 paths. The reason it looks 
like an icon and not a photorealistic scene is tied directly to 
the sequential representation: longer command sequences mean more 
accumulated error, so the training data and therefore the outputs 
stay simple. A designer could open that file and rearrange things. 
SVGDreamer generates the same subject using somewhere between 256 
and 512 optimized B\'{e}zier 
paths~\cite{xingSVGDreamerTextGuided2024}. The result is visually 
rich but structurally opaque, because most of those paths overlap 
and do not correspond to any recognizable component. NeuralSVG 
renders its rocket with exactly 16 shapes, each mapped through an 
MLP~\cite{polaczekNeuralSVGImplicitRepresentation2025}. That is 
a roughly 30x reduction in element count for the same subject. And SVGFusion 
sits in between, producing roughly 10 to 20 structured shapes 
including not just B\'{e}zier paths but also basic SVG elements 
like circles and 
rectangles~\cite{xingSVGFusionScalableTexttoSVG2025}, because its 
latent space was trained on real SVG files that use the full 
primitive vocabulary.

What this comparison reveals is that the number of shapes a model 
produces, and whether those shapes correspond to anything 
meaningful, matters more for practical editability than which 
representation family the model belongs to. Parametric 
representations should in theory be the most editable since every 
shape is an explicit geometric object. But that advantage vanishes 
when the path count gets into the hundreds. Sequential and latent 
representations produce compact output, but within bounded domains. 
Implicit representations give the cleanest decomposition, but at 
a computational cost that limits practical use.

What actually seems to drive clean structure is not the 
representation itself but what constraints are placed on it. 
Methods that use segmentation masks to initialize primitives 
(SAMVG)~\cite{zhuSAMVGMultistageImage2023}, saliency maps to place shapes (NeuralSVG)~\cite{polaczekNeuralSVGImplicitRepresentation2025}, or 
construction-sequence training data (LayerTracer)~\cite{songLayerTracerCognitiveAlignedLayered2025} all produce 
outputs with clearer boundaries regardless of their underlying 
representation type. LayerTracer is the clearest example: 
editability there is something the model was explicitly taught. 
Representation defines what kinds of structures are possible, but 
initialization and supervision determine whether useful structure 
actually shows up in the output.


\section{Summary}


Representation defines what kinds of structures a model can 
produce, but not which ones it will produce. That depends on 
supervision: what signal drives generation and where it pushes 
the geometry. The next chapter examines those signals.
